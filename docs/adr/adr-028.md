# ADR-028 : Accès à la base de données

- **Statut :** Décidé le 23 novembre 2026.

## Contexte

Les fiches fixent les règles que l'accès aux données doit respecter : chaque module possède ses tables, sans jointure entre modules, et aucune entité ne traverse une frontière (ADR-022) ; insertion idempotente par clé naturelle (ADR-027) ; Spring Batch avec un dépôt de métadonnées JDBC (ADR-009) ; instantanés figés et journal d'audit en ajout seul (ADR-026). Aucune fiche ne choisissait la technologie d'accès à la base.

## Décision

Spring Data JDBC pour les objets métier de chaque module : un dépôt par agrégat, les références entre agrégats par identifiant, les dépôts dans la couche `infrastructure` du module. JdbcClient pour le SQL explicite : insertion idempotente (`INSERT … ON CONFLICT DO NOTHING`) et agrégats par segment. Flyway pour les migrations, dans la version 11.20.3 (propriété `flyway.version` du pom), car la version gérée par Spring Boot 3.5.16 (11.7.2) déclare PostgreSQL 17 comme dernière version testée. Ni JPA ni jOOQ à ce stade.

## Preuves

- Spring Boot 3.5.16 est testé jusqu'à Java 25 [108] et gère Hibernate 6.6.53, Flyway 11.7.2, jOOQ 3.19.35 et Spring Data JDBC 3.5.13 [109]. Les deux dernières valeurs viennent d'un résumé de la page, non relue mot pour mot.
- Hibernate ORM 6.6 est en « limited support » : correctifs seulement pour les bogues jugés importants, passage à une série plus récente recommandé ; Java 25 est supporté à partir de la 6.6.40 [110]. Le HQL 6.6 accepte `insert … on conflict` [117].
- jOOQ, édition open source sous licence Apache 2.0 [112] : PostgreSQL est pris en charge ; dans la matrice des JDK, les versions 3.20 et 3.21 sont listées pour Java 21, Java 25 apparaît pour la 3.22 [111].
- Spring Data JDBC : pas de chargement paresseux, pas de suivi des modifications, pas de session ; une référence entre agrégats est un identifiant, un dépôt par racine d'agrégat [113].
- Le registre des publications d'événements de Spring Modulith 1.4 a un démarreur JDBC qui fonctionne aussi sans JPA [114]. JdbcClient est disponible depuis Spring 6.1 [115].
- Essai dans le dépôt (PR #35), sur PostgreSQL 18.7 en conteneur : Spring Data JDBC enregistre et relit un agrégat ; l'insertion idempotente en deux appels ne crée qu'une ligne ; un travail Spring Batch relancé avec les mêmes paramètres est refusé ; le registre d'événements est créé. Flyway 11.7.2 affichait « the latest supported version of PostgreSQL is 17 » ; l'avertissement disparaît avec la 11.20.3. La page de Flyway liste PostgreSQL 18 parmi les versions vérifiées sans dire depuis quelle version [116].

## Conséquences

Les requêtes SQL sont des chaînes de texte, vérifiées à l'exécution et non à la compilation : les tests d'intégration avec un PostgreSQL réel (ADR-016) sont obligatoires pour toute requête. Enregistrer un agrégat existant supprime puis réinsère ses éléments liés [113] : les agrégats restent petits, et une collection volumineuse passe par du SQL direct. La règle « aucune entité à travers une frontière » devient la façon normale de modéliser (référence par identifiant), pas une discipline à surveiller. La version de Flyway est fixée à part de Spring Boot : à revérifier à chaque changement de version de Spring Boot. Le choix reste réversible module par module tant qu'un module n'a pas écrit son code d'accès aux données.

## Points non vérifiés

Support officiel de PostgreSQL 18 par Hibernate 6.6 ; présence d'`onConflictDoNothing` dans le manuel de jOOQ (elle figure dans la Javadoc) ; date de fin du support open source de Spring Boot 3.5 ; comportement de Spring Batch 5.2 au-delà du travail minimal essayé (la documentation lue était celle de la version 6.1). Aucune notation chiffrée des options : les poids des critères n'ont pas été fixés, la décision s'appuie sur les faits ci-dessus.

## Alternatives

Spring Data JPA avec Hibernate (série en support limité, règle des frontières à surveiller à chaque relecture) ; jOOQ (la version gérée par Spring Boot est classée Java 17, Java 25 n'est listé que pour la 3.22 : à rouvrir pour Analytique si une version listée pour Java 25 est confirmée) ; JdbcClient seul (même code d'enregistrement réécrit dans chaque module).
