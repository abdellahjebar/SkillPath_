# ADR-016 : Stratégie de tests

- **Statut :** Décidé le 8 novembre 2026.

## Décision

Pyramide de tests : tests unitaires des formules avec des valeurs de référence calculées indépendamment, tests d'intégration avec un PostgreSQL réel en conteneur, vérification des modules avec dépendances autorisées déclarées, tests de conformité (contrat sans texte complet par défaut, sortie externe journalisée, droits par rôle, CSRF), tests de reprise, de rejeu, de téléchargement tronqué et d'adaptateurs de source, tests de l'interface et deux ou trois parcours de bout en bout ; garde-fou d'évaluation de l'extraction sur le jeu de développement dans la CI, test gelé à la demande ; jeux d'exemple synthétiques, aucun test ne lit les exports privés.

## Preuves

Beaucoup de tests rapides, peu de tests de bout en bout, qui sont lents et instables [74] ; la base en mémoire H2 n'émule qu'un sous-ensemble des différences entre bases [75] ; tests de module avec simulation des dépendances [51].

## Notation préliminaire

Pyramide avec jeux de référence et conformité 240 sur 300, pyramide avec vraie base 190, avec base H2 170, bout en bout 100, manuel 80.

## Conséquences

Les régressions de conformité sont détectées automatiquement ; effort d'écriture plus élevé ; Docker requis pour les tests d'intégration.

## Alternatives

Tests manuels ; base en mémoire ; bout en bout dominant.
