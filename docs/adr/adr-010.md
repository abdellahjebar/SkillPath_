# ADR-010 : Méthode d'extraction des compétences

- **Statut :** Proposé.

## Décision proposée

Correspondance de termes en Java derrière une interface unique, mesurée sur le jeu annoté, puis racinisation française. Les embeddings en Python sont testés hors production pour décider d'un éventuel service.

## Preuves

Précision, rappel et mesure F1 [62] ; accord entre annotateurs mesuré par le F1 entre annotateurs, le pourcentage d'accord et le kappa, sans seuil fixé d'avance [95, 63] ; jeu de test gelé, jamais utilisé pour régler [92] ; Lucene propose des filtres de racinisation, pas de lemmatisation [64] ; ESCOXLM-R est un encodeur à réajuster, pas un extracteur prêt à l'emploi [38] ; les conditions d'utilisation de la source limitent la communication à des tiers [13].

## Notation préliminaire

Grille sur 210 sans le critère d'exactitude, qui sert de seuil de mesure : termes seuls 210, termes et racinisation 200, service Python 130, embeddings en Java 120, modèle externe 80.

## Conséquences

Déterministe, local, explicable ; rappel limité sur les formulations indirectes ; l'effort principal est l'annotation du jeu.

## Alternatives

Embeddings en Java ; service Python ; modèle de langage externe.
