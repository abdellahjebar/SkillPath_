# ADR-010 : Méthode d'extraction des compétences

- **Statut :** Décidé le 8 novembre 2026 ; le composant Python dépend des mesures (ADR-018 et ADR-019).

## Décision

Correspondance de termes en Java derrière une interface unique, dans le module Extraction, mesurée sur le jeu annoté, puis racinisation française, puis embeddings prêts à l'emploi (EmbeddingGemma, BGE-M3, multilingual-e5-large-instruct) et hybride. Un conteneur Python d'embeddings est un adaptateur conditionnel : retenu seulement si le gain atteint cinq points de F1 avec un intervalle bootstrap apparié excluant zéro. Le dictionnaire reste actif comme plancher et repli.

## Preuves

Précision, rappel et mesure F1 [62] ; accord entre annotateurs mesuré par le F1 entre annotateurs, le pourcentage d'accord et le kappa, sans seuil fixé d'avance [95, 63] ; jeu de test gelé, jamais utilisé pour régler [92] ; Lucene propose des filtres de racinisation, pas de lemmatisation [64] ; ESCOXLM-R est un encodeur à réajuster, pas un extracteur prêt à l'emploi [38] ; les conditions d'utilisation de la source sont à traiter avant déploiement, l'envoi de texte à un service externe étant explicite et journalisé [13].

## Notation préliminaire

Grille sur 210 sans le critère d'exactitude, qui sert de seuil de mesure : termes seuls 210, termes et racinisation 200, service Python 130, embeddings en Java 120, modèle externe 80.

## Conséquences

Déterministe, local, explicable ; rappel limité sur les formulations indirectes ; l'effort principal est l'annotation du jeu.

## Alternatives

Embeddings en Java ; service Python ; modèle de langage externe.
